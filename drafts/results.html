Reviewed findings

  • C1/pdfsig PARTIAL (documented_behavior): Reports "Not total document signed" and a valid signature. Its output has no field that classifies a later change, so it reports coverage without judging it.
  • C2/pdfsig PARTIAL (documented_behavior): Reports "Not total document signed" and a valid signature. Its output has no field that classifies a later change, so it reports coverage without judging it.
  • C2/dss PARTIAL (documented_behavior): The object changes are all SignatureOrFormFill. The filled value also gives a visual difference warning, documented at WARN in the default policy. The mapping counts that as an other warning, which is why this is not an allowed change.
  • C3/pdfsig PARTIAL (documented_behavior): Reports "Not total document signed" and a valid signature. Its output has no field that classifies a later change, so it reports coverage without judging it.
  • C3/dss PARTIAL (documented_behavior): TOTAL_PASSED with a DocMDP warning. The default policy documents DocMDP at WARN, so it reports the violation and does not fail the signature. A stricter policy could.
  • C4/pdfsig PARTIAL (documented_behavior): Reports "Not total document signed" and a valid signature. Its output has no field that classifies a later change, so it reports coverage without judging it.
  • C4/dss PARTIAL (documented_behavior): TOTAL_PASSED with visual difference and undefined change warnings. The default policy documents both at WARN, so it reports the change and leaves the decision to the reader.
  • C5/pdfsig PARTIAL (documented_behavior): Reports "Not total document signed" and a valid signature. Its output has no field that classifies a later change, so it reports coverage without judging it.
  • C5/dss PARTIAL (documented_behavior): TOTAL_PASSED with visual difference and undefined change warnings. The default policy documents both at WARN, so it reports the change and leaves the decision to the reader.
  • A3/pdfsig PARTIAL (documented_behavior): Reports "Not total document signed" and a valid signature, which is accurate for a gap wider than /Contents. It does not say the signature structure is nonstandard.
  • B5/pyhanko MISSED (documented_behavior): ValidationContext defaults to revocation_mode soft-fail, so an unreachable source does not change the result. The kit keeps that default. This is the API default, and the CLI has its own revocation options, which were not run.
  • E2/pdfsig MISSED (documented_behavior): Its output has no field for a signature timestamp, so an untrusted timestamp cannot change the result.
  • E2/dss MISSED (oracle_disputed): TOTAL_PASSED, and the timestamp is reported separately as INDETERMINATE, NO_CERTIFICATE_CHAIN_FOUND. DSS does not use it as proof of time, and the signature stands at the validation time. The oracle's policy says offered but unproven evidence is insufficient. The expected value is unchanged, and this is for the owner to decide.
